### 2.3 一个刻意的顺序约束（避免 ESM 循环 + TDZ）

`OnboardingStepSchema` 定义在 `packages/shared/src/proactive.ts` 而**不是** `ipc.ts`，
因为 `settings.ts` 的 `AppSettingsSchema.onboarding.step` 需要它，而 `ipc.ts` 需要 `settings.ts` ——
若枚举放在 `ipc.ts` 就是 `ipc → settings → ipc` 的 ESM 循环，而 zod schema 在模块求值期构造，
会踩 TDZ 崩。`ipc.ts:657-665` 只做**转发导出**，让「契约都在 ipc.ts」的阅读习惯继续成立。

### 2.4 向导判据里两条容易漏掉的语义

- **"配了供应商" ≠ "配好了"**：`hasProvider = providers.length > 0 && active !== null && store.has(active.id)`
  —— 加了供应商但没填密钥**仍不算满足**（单测有★用例）。
- **换供应商会作废上一次的测试通过记录**：`ipc.ts:566-572` 的 `provider:select` 会调
  `recordOnboardingTest(input.id, false, 'switched')`；测试失败时 `recordOnboardingTest` 把
  `lastTestOk` 直接置 `null`（`onboarding-store.ts:76-80`）—— 不能拿旧的"通过"解锁新配置。

## 3. 向导六步与主进程判据

### 3.1 判据表（`onboarding-store.ts:119-135`）

| 步骤 | 主进程判据（可机械复核） |
|---|---|
| `provider` | 至少一个供应商，且**生效的那个**在 secrets-store 里有密钥 |
| `test` | `lastTestOk !== null` 且 `lastTestOk.providerId === active.id`（必须是**当前生效**供应商） |
| `model` | 生效供应商的 `model.trim().length > 0` |
| `persona` | 人设 `name` 与 `userTitle` 都非空 |
| `permission` | 权限表非空，且所有 `effective === 'blocked'` 的能力 `enabled === false` |
| `schedule` | 静音时段 `updatedAt > 0`（用户至少确认过一次）**或**已存在日程 |

> 首装时 `persona` 与 `permission` 即满足（默认人设已有名字与称呼、权限默认全部关闭或禁止）。
> 单测如实断言了这一点：`{provider:false, test:false, model:false, persona:true, permission:true, schedule:false}`，
> `blockedBy === 'provider'`。这是**刻意的**：这两步的意义是"用户确实看过这一页"，不是"必须改动点什么"。

### 3.2 `HINTS` 原文（`onboarding-store.ts:169-176`，逐字引用）

```
provider:   '请先添加一个供应商（baseURL + 模型 + API Key），密钥只在本机加密保存'
test:       '请点「测试连接」——必须真的连通才能继续（未验证的配置不会进入日常使用）'
model:      '请选择或填写模型名'
persona:    '请设置她的名字，以及她怎么称呼你'
permission: '请确认权限页：高风险能力（支付/改密码/读凭据）永远是「禁止」，无法被开启'
schedule:   '请确认静音时段与隐私设置（哪段时间不打扰你）'
```

`blockedBy === null` 时 `hint = '全部就绪'`；若密钥后端不是 `safeStorage`，hint 会被**覆盖**成
`注意：密钥后端为 <name>，密钥无法加密保存（拒绝降级为明文）`（`onboarding-store.ts:155-158`）。

### 3.3 拒绝跳步

```ts
// apps/desktop/src/main/ipc.ts:624-634
guarded(IPC.ONBOARDING_COMPLETE, OnboardingCompleteSchema, (input) => {
  if (input.completed) {
    const st = onboardingStatus()
    // **不许跳过未满足的步骤**：向导的意义就是"每一步都真的做过"
    if (st.blockedBy !== null) {
      return err('ONBOARDING_INCOMPLETE', `还有未完成的步骤：${st.blockedBy}（${st.hint}）`)
    }
  }
  completeOnboarding(input.completed)
  return { ok: true, status: onboardingStatus() } as unknown as Result
})
```

单测覆盖到的是**判据函数**（`st.blockedBy !== null` ⇒ ipc 层据此拒绝），
**不是**一次真实的 IPC 往返（那需要启动应用，见 §6.2）。
