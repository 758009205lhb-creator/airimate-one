# 浸泡分析器的严谨化（A15/A16 的判定工具本身）

**背景**：2 小时浸泡的判定不在"跑没跑"，而在**分析器会不会说谎**。
本轮把分析器从"能出结论"改成"结论能经得起复核"，过程中修掉 4 个自己的错误。

---

## 1. 采样混叠：**不能**把"观测到 4 个 clip"当成"只轮换了 4 个"

实测数据（30s 采样、12s 轮换、17 分钟）：

```
idleIndex 序列: 0 3 5 8 0 3 5 8 0 3 5 8 …（严格重复）
```

一眼看上去像"只轮换了 4 个待机动作"。**这是误读**：
30 ÷ 12 = **2.5** 个 index/样本，而 index 只取整数 ⇒ 观测序列必然**混叠**，
重复周期 = 10 个 clip × 12s = **120s**（恰好一整轮），而 30s × 4 = 120s ⇒ 每 4 个样本一轮。

> 这类问题的危险在于：它会让人**去修一个并不存在的 bug**
> （"为什么只轮换 4 个？"），而真正的信息在序列的**步长规律**里。

## 2. 修掉的 4 个自己的错误（每一个都给出过错误结论）

| # | 我写的判据 | 算出来的值 | 为什么错 |
|---|---|---|---|
| 1 | `step` 唯一值个数 = 1 视为"稳定" | 唯一值是 {2,3} ⇒ 判"轮换不规律" | 2.5 个/样本必然在整数间交替，**交替才是正常** |
| 2 | `phase = (index − t/12) mod 1` 取小数 | 漂移 **99.45%** | 2.5 个/样本 ⇒ 相位本身每两个样本差 0.5，那是**拍频**不是漂移 |
| 3 | 残差对时间做最小二乘斜率 | 漂移 **497.98%** | 在**欠采样**的整数序列上估斜率，得到的是量化抖动的拟合，无物理意义 |
| 4 | 网格搜索周期使残差方差最小 | 周期 **12.9995s**（偏差 8.3%） | 落进**混叠谐波**的假极小值（残差方差 704 = 拟合极差） |

四次都"能跑出一个数"，四次都错。共同根因：**在欠采样序列上做连续量统计**。

## 3. 现在用的判据（严谨且直观）

### 3.1 周期：由平均步长反推，并给出**不确定度区间**

```
每样本平均步长 = 2.5128（n=39，sd=0.5064，se=0.0811）
周期 = 30 / 2.5128 = 11.939 s
68% 区间 = [11.566, 12.337] s   ← **把判据的 12s 包住**
偏差 = −0.51%
```

不确定度来自步长本身的抽样误差（整数化带来的量化噪声）。**区间必须把 12s 包住**才算通过 ——
只报一个点估计会掩盖"采样精度不足以区分 12.0 与 12.3"。

### 3.2 无累积漂移：**模式复现**

```
每 4 个样本一循环，9 组中错位 0 处（不匹配率 0%）
```

原理：周期准确 ⇒ "每样本前进 2.5 个 index"这个规律会让观测序列**精确重复**。
把序列按 4 个一组切开，**各组逐元素相同**；周期只要偏一点，若干组后就会错位。
这等价于"在 120s（=10×12s，恰好一整轮）的整数倍窗口内无相位漂移"，
**完全不受量化抖动影响** —— 这是对上面 4 个错误方案的替代。

### 3.3 交叉验证：残差极差在前后两半应同量级

```
残差极差：前半 40.542，后半 50.542（差 10.0 = 恰好一个量化单元）
```

若存在累积漂移，后半的极差会显著大于前半。

### 3.4 堆斜率：**窗口不足时不下结论**

实测教训：20 分钟窗口上斜率在 **0.39~0.56** 之间摆动（阈值 0.5）——
纯粹是短窗口噪声，会让同一份数据**忽而 PASS 忽而 FAIL**。

判据 A16 本来就是"2 小时无持续增长"，所以在不足 30 分钟的数据上记为
**"未判定"**（`heapSlopeDecidable=false`），而不是假装通过或失败。

## 4. 时长闸门（最重要的那条）

`A15-soak-summary.json` 是分析器对**任意一份** JSONL 的产物。
我校验分析器时用 `--MinSoakSec 200` 分析过一份 **4 分钟**的数据，
那份报告里 `passA15=True`。

**验收覆盖审计第一次运行就把它读成了 A15/A16 PASS** ——
若不加闸门，交付报告会写"2 小时浸泡通过"，而实际当时只跑了 10 分钟。

⇒ 审计侧加了 `requireField: { path: 'actualSoakSec', min: 7200 }`；
分析器侧保留 `--MinSoakSec` 供校验用，但**正式判定必须用默认的 7200**。
